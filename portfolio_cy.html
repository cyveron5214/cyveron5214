02 — About

Who I am

I'm a self-taught developer from Asia — currently a student who builds things to understand them.

I got into code because I wanted to make games. Turns out making games teaches you physics, math, rendering, systems design — basically everything interesting about programming.

My rule: no game engines, no heavy frameworks. If I can't build it myself, I don't understand it. That means every collision system, every particle, every orbital calculation is written from scratch.

I'm also genuinely curious about web security and how systems fail. Understanding how things break is just as important as knowing how to build them.

I use AI as a learning tool — to explore ideas faster, understand concepts deeper, and push code further than I could alone. But the understanding has to be mine.

Right now: student by day, vibe coder by night.

03 — Philosophy

How I think about code

A few principles I've picked up from building things the hard way.

// 01
No black boxes
If I use it, I understand it. No copying physics engines without knowing the math. No animation libraries without knowing what's happening each frame.
// 02
Ship broken, fix fast
A working prototype with bugs beats a perfect plan that never ships. Get something on screen, then iterate. Perfection is the enemy of learning.
// 03
Build what excites you
Space simulations and arcade games aren't practical projects — they're passion projects. And passion projects teach more than assignments ever do.
// 04
Curiosity over credentials
I'm self-taught. No CS degree, no bootcamp. Just a browser, a text editor, and genuine curiosity about how things work.
